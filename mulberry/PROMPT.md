Ты senior-разработчик мобильных игр (HTML5/JS, Capacitor, Android) и Python-бэкенда. Работаешь в папке с исходниками моей игры MULBERRY. Сначала прочитай README.md и CHANGELOG.md — там архитектура и мои прошлые решения.

## Задача
Сделать из игры полноценное Android-приложение (APK-файл), которое я выложу в свой Telegram-канал: «скачивайте, вот моя игра». И перевести игру в ГОРИЗОНТАЛЬНУЮ ориентацию.

## Что должно получиться
1. Горизонтальная вёрстка (landscape) всех экранов: главная, выбор игры, все 8 игровых столов, магазин, инвентарь, профиль, онлайн-комнаты. Эталон: телефон 844x390 и 740x360 (плюс вырез камеры — учитывай `env(safe-area-inset-*)`). Стол во всю ширину, игроки по дуге, кнопки действий справа или снизу так, чтобы ничего не налезало и всё нажималось большим пальцем. Портретная вёрстка для Telegram Mini App должна продолжать работать как сейчас: делай через `@media (orientation: landscape)` в том же index.html, логику игр не трогай.
2. Android-приложение на Capacitor: обёртка над `client/` (все картинки, звуки, шрифты лежат внутри APK, грузится мгновенно). Только альбомная ориентация, полный экран без системных панелей, тёмный фон #0d090b, иконка и сплэш из логотипа (client/c/), название MULBERRY, пакет например `club.mulberry.game`. Кнопка «Назад» Android = то же, что BackButton Telegram в игре.
3. Вход вне Telegram с тем же аккаунтом (тот же баланс и скины). Сейчас api.py проверяет Telegram `initData`, в приложении его нет. Сделай вход через бота: приложение получает одноразовый код от API → открывает `https://t.me/MulberryPokerBot?start=login_<код>` → бот (bot.py) на этот /start привязывает код к Telegram id и отвечает «Вход выполнен, вернитесь в игру» → приложение опрашивает API и получает долгий токен сессии (хранить в Preferences/localStorage). api.py принимает ИЛИ initData, ИЛИ токен сессии. Коды живут 5 минут, одноразовые; токен подписан HMAC секретом сервера. Кнопка «Выйти» в профиле.
4. Сеть: в приложении API по абсолютному адресу `https://2-56-120-214.sslip.io/monaco/api/` (сертификат Let's Encrypt, валидный). Добавь в api.py CORS для origin приложения (`https://localhost`) или используй CapacitorHttp — выбери одно и объясни почему. Всё, что в клиенте завязано на `Telegram.WebApp` (haptic, имя/аватар, приглашения через openTelegramLink, цвета шапки), — через тонкую обёртку с безопасными заглушками вне Telegram (вибрация — через Capacitor Haptics, приглашение — системное «Поделиться» со ссылкой на бота).
5. Проверка обновлений: при старте приложение спрашивает у API текущую версию; если APK старее — плашка «Вышло обновление» с кнопкой, открывающей мой канал. Больше никаких новых фич.
6. Сборка APK без Android Studio у меня: GitHub Actions workflow, который собирает подписанный release-APK и выкладывает его артефактом. Ключ подписи (keystore) — сгенерировать один раз, хранить в GitHub Secrets; напиши мне по шагам, что нажать в GitHub (я школьник, объясняй просто). Важно: обновления APK ставятся поверх только с тем же ключом — предупреди, чтобы я сохранил keystore в надёжном месте.

## Правила
- Сначала пришли короткий план (что меняешь, какие файлы, какие решения) и жди моего «да». Не раздувай: только перечисленное выше.
- Не меняй игровую логику, баланс, цены, каталог скинов и дизайн (тёмная тема «клуб», акцент #e3305f). Не добавляй чужих логотипов.
- index.html большой (~430 КБ): не читай его целиком много раз — ищи нужные места через grep, правь точечно. Береги токены.
- Сервер ты не трогаешь напрямую: изменённые `server/api.py` и `server/bot.py` отдай отдельно со списком изменений и командами проверки — их выкатит админ сервера. Изменения должны быть обратно совместимы с текущей Telegram-версией.
- После каждого этапа проверяй сам: открой index.html в headless-браузере (puppeteer, как tests/smoke.js) в 844x390 и 390x700, сделай скриншоты всех экранов и столов, убедись, что нет наложений, обрезанных кнопок и ошибок в консоли. «Готово» — только после проверки.
- Секреты (токен бота, keystore, пароли) не клади в код и в репозиторий.
